# NMT pipeline (NLLB-200 + LoRA + semantic reranking)
# Pinning strategy: exact pins on the ML / eval stack (anything that affects
# model behavior or reported metrics), looser ranges on glue libs (numpy with
# upper bound, pandas, sklearn, tqdm, pyyaml, pyarrow, matplotlib).
#
# Deviations from plan.md (documented in the thesis methodology):
#   1. Python: plan §6 prescribes 3.11, we use 3.12 to align with pyproject.toml.
#   2. numpy: plan §7 prescribes numpy==2.2.6, but unbabel-comet 2.2.4 hard-pins
#      numpy<2.0.0. We use numpy>=1.26,<2 to satisfy COMET. COMET is non-
#      negotiable per plan §30.
#   3. setuptools<81: pkg_resources was removed in setuptools 81+ but
#      torchmetrics (transitive dep of unbabel-comet via pytorch_lightning)
#      still imports it. Pin under 81.
#   4. torch bumped 2.5.1 -> 2.7.1 to support Blackwell consumer GPUs
#      (sm_120, RTX 50 series). Plan §7 fixed torch==2.5.1 which does not
#      have prebuilt CUDA kernels for sm_120; bumping is required to use
#      the available hardware. transformers/accelerate/peft bumped accordingly.
#   5. Glue libs use ">=" instead of "==" (project decision: middle-ground).
#   6. sentence-transformers bumped 4.1.0 -> >=5.4.1,<6. The frozen
#      v3_iterative_hn_e5_base_bidirectional checkpoint was saved with
#      sentence-transformers 5.4.1 and uses the new module paths
#      (sentence_transformers.base.modules.transformer.Transformer plus
#      transformer_task / modality_config / include_prompt kwargs). 4.1.0
#      cannot load it. Verified working on this Windows host with 5.4.1.
#
# CUDA install (Windows + RTX 5060 Ti, sm_120 / Blackwell, driver 596.36 /
# CUDA 13.2-capable): the torch line below uses PyPI default wheels (CPU).
# Install the cu128 build first, then the rest of this file:
#   pip install torch==2.7.1 --index-url https://download.pytorch.org/whl/cu128
#   pip install -r requirements/nmt.txt
# Verify with:
#   python -c "import torch; print(torch.cuda.is_available(), torch.version.cuda)"
